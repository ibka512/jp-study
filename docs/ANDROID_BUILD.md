# 安卓打包与上架说明（钟日）

这篇文章写给不懂代码的自己：照着点、照着复制就行。

---

## 一、这个仓库现在会自动做什么

每次代码合并到 `main` 分支（或在 Actions 页面手动点「Run workflow」），GitHub 会在云端自动完成：

1. 把网页版文件打包成安卓工程；
2. 把界面字体和图标**下载并内置到安装包里**（离线、国内网络都能正常显示）；
3. 生成应用图标和启动画面；
4. 适配安卓 15 的全屏显示（内容不会被状态栏挡住）；
5. 编译出可以直接安装的 **测试版 APK**；
6. 如果你配置好了「发布签名」（见下文第三节），还会额外编译出**上架用的正式版 APK 和 AAB**。

整个过程约 10～20 分钟，不需要在自己电脑上安装任何软件。

---

## 二、怎么下载并安装到手机（日常自己用）

1. 打开仓库页面，点顶部的 **Actions**；
2. 点左侧的 **「构建钟日 Android 安装包」**，再点最新一次运行记录（绿色对勾表示成功）；
3. 把页面拉到最下面的 **Artifacts（产物）** 区域；
4. 下载 **`zhongri-android-debug`**，解压得到 `app-debug.apk`；
5. 把 APK 发到手机（微信文件传输、数据线、邮箱都行），点击安装；
   - 手机会提示「不允许安装未知来源应用」，按提示允许一次即可；
   - 覆盖安装不用卸载旧版，学习数据会保留（同一签名直接升级）。

> 测试版和正式版的区别：测试版用机器自动生成的测试签名，只能自己装着用，商店不收；正式版用你的专属密钥签名，可以上架。

---

## 三、上架前的一次性准备：配置发布签名（约 15 分钟，只做一次）

商店要求每个 App 有一个「专属印章」（密钥库），以后每次更新都必须用同一个印章，**丢了就永远没法更新已上架的 App**。请认真做备份。

### 第 1 步：在自己电脑上生成密钥库文件

电脑上需要先装有 Java（没装过的话，搜「Adoptium Temurin 21」下载安装，一路下一步）。

- **Windows**：按 `Win + R`，输入 `cmd` 回车，粘贴下面这行后回车：

  ```
  keytool -genkeypair -v -keystore zhongri-release.keystore -alias zhongri -keyalg RSA -keysize 2048 -validity 10000
  ```

- **Mac**：打开「终端」，粘贴同样一行后回车。

它会依次问你几个问题，照这样填：

| 问题 | 怎么填 |
| --- | --- |
| 输入密钥库口令 | **自己想一个密码，写下来！**（输入时屏幕不显示，是正常的） |
| 再次输入新口令 | 再输一遍同一个密码 |
| 名字与姓氏 / 组织单位 / 城市… | 随便填或一路回车跳过 |
| 是否正确 | 输入 `是` 回车 |
| 密钥口令（直接回车 = 和密钥库相同） | **直接回车**（两个密码保持一致最好记） |

完成后，当前文件夹里会出现 `zhongri-release.keystore` 文件。

> ⚠️ **这个文件和密码等于你的 App 的所有权。** 请立刻把它复制到至少两个安全的地方（如 U 盘 + 网盘加密文件夹），密码写在自己不会丢的本子上。不要发给任何人，也不要上传到仓库（仓库已设置为自动忽略它）。

### 第 2 步：把密钥库转换成一行文本

- **Windows**（在密钥库所在文件夹，按住 Shift 点右键 →「在此处打开 PowerShell 窗口」）：

  ```powershell
  [Convert]::ToBase64String([IO.File]::ReadAllBytes("zhongri-release.keystore")) | Set-Clipboard
  ```

  运行后那行长文本已经**复制到剪贴板**了。

- **Mac**（终端里先 `cd` 到密钥库所在文件夹）：

  ```bash
  base64 -i zhongri-release.keystore | pbcopy
  ```

### 第 3 步：把机密信息存进 GitHub 保险箱

1. 打开仓库页面 → 顶部 **Settings** → 左侧 **Secrets and variables** → **Actions**；
2. 点 **New repository secret**，逐个添加下面 4 条（Name 必须一字不差）：

| Name | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | 第 2 步复制到剪贴板的那行长文本（直接粘贴） |
| `ANDROID_KEYSTORE_PASSWORD` | 第 1 步你想的那个密码 |
| `ANDROID_KEY_ALIAS` | `zhongri` |
| `ANDROID_KEY_PASSWORD` | 还是第 1 步那个密码（当时选了回车=相同） |

### 第 4 步：完成

之后每次构建，Artifacts 里会多出一个 **`zhongri-android-release`**，里面有两个文件：

- **`app-release.apk`** → 用于国内安卓商店（华为、小米、OPPO、vivo、应用宝等）；
- **`app-release.aab`** → 用于 Google Play（只收 AAB）。

## 四、每次发布新版本前要做什么

商店不接受「版本号不变」的更新包。所以每次准备发版前：

1. 打开仓库里的 `package.json`，把 `"version": "1.0.0"` 改大一点（比如 `1.1.0`），提交；
2. 构建号（versionCode）云端会用运行次数自动累加，不用管。

---

## 五、上架时商店会要的其他材料（提前准备）

- **应用名称**：钟日；**包名**（已固定）：`com.ibka.zhongri`；
- **图标**：已自动生成（用仓库里的 logo.png）；
- **应用简介、截图**：手机装好测试版后自己截几张即可；
- **隐私政策**：国内商店强制要求。要点：学习数据只保存在用户本机；AI 功能会把用户主动发送的内容传给 DeepSeek（用户自行填写自己的密钥）；词库来源与许可见仓库 `THIRD_PARTY_WORD_BANKS.md`；
- **国内商店**通常还要：软件著作权证书（软著，可网上申请，约 1～2 个月）、各商店开发者账号（部分要企业资质）；
- **Google Play** 需要一次性 25 美元开发者账号费，并填写数据安全问卷。

## 六、安装包大小说明

词库约 7 MB + 内置离线字体若干 MB，最终 APK 预计在 **30～45 MB** 左右，属于正常范围。

---

## 七、出问题了怎么办

1. 打开 Actions 页面，点进那次**红色叉**的运行记录；
2. 点左侧失败的那一步，把页面里**红色的报错文字**复制下来；
3. 原样发给 AI 助手（也就是我），说一句「安卓构建失败了，这是报错」。

不需要理解报错内容，原样复制就行。

---

## 附：名词小词典

- **APK**：安卓安装包文件，手机直接安装用；
- **AAB**：Google Play 专用的上架格式，手机不能直接装；
- **签名 / 密钥库（keystore）**：证明「这个 App 是你开发的」的专属印章文件；
- **Artifacts**：GitHub 构建完成后生成的可下载文件；
- **Secrets**：存在 GitHub 上的加密保险箱，只有构建机器能读，别人（包括你自己在页面上）都看不到内容。
