# 数据完整性与回归验证

词库仍按语言延迟加载。未加载语言的收藏、错题、内置词覆盖和删除标记必须保留，不能把当前 `Model.db` 视为完整有效 ID 集合。用户明确删除词条或重置数据时，继续由对应操作清理引用。

## 主存储与备用写入

- IndexedDB 原有键名、值结构及旧版 localStorage 读取兼容性保持不变。
- IndexedDB 不可用或写入失败时，将完整的新值写入 localStorage 的 `zhongriPendingStorage_v1:<原键名>`，作为待同步副本。该单次写入同时保存数据与“未同步”的状态。
- 只要待同步副本存在，读取优先使用它，即使 IndexedDB 已恢复。读取不改写数据。
- 对同一个键的下一次保存成功写入 IndexedDB 后，才清除对应待同步副本。再次写入失败时更新待同步副本。
- 清除导入恢复点通过保存 `null` 完成，避免旧主存储记录在恢复后重新出现。
- 没有待同步副本时，仍按原有规则读取 IndexedDB，再回退到旧 localStorage 键。不会猜测升级前两份无时间戳数据哪份更新，也不会直接删除旧副本。

这是新增备用记录的兼容修复，不批量迁移现有用户数据。若需要回退代码，应保留待同步副本的读取兼容，或者先在新版导出完整备份、确认所需数据已成功同步到 IndexedDB。不要仅删除待同步键来回退。旧版本已经丢失的数据需要从有效备份恢复，程序无法重建缺失内容。

## 自动检查

```sh
npm test
python3 -m unittest discover -s tests -p 'test_*.py' -v
npm run build:web
```

`npm test` 包括以下行为检查：

- 完整 `app.js` 的双向语言切换、重启、编辑和删除标记保留。
- 完整备份导入后再重启，保留收藏、错题、释义和 FSRS。
- 主存储失败、备用保存、重启、恢复后的读取和继续保存。
- 实际首页脚本序列的按语言启动与切换加载。
- Service Worker 执行真实资源清单，并核对首页当前资源 URL 是否进入预缓存。
- Android HTML 适配处理实际首页及变化后的缓存参数，不在单元测试中下载字体。
- 原生提醒桥执行真实规划逻辑，在平台适配边界使用内存模拟，验证通知调度、取消、前台重排、权限拒绝和推迟。

Python 编译器端到端测试会在临时副本生成词库，然后运行该副本的加载器、首页加载和 Service Worker 测试。词条数量正确不能替代运行时兼容性检查。

浏览器交互和 Android 真机行为仍应按发布范围验证。Node 测试中的 DOM、IndexedDB 与 Capacitor 适配器不等于浏览器或 Android 操作系统本身。
